🛡️ 1. Isolation Logicielle Stricte

Toutes les requêtes de l'API FastAPI (lecture, création, modification, suppression) exécutées sur users, projects et tasks appliquent impérativement le filtre MongoDB {"company_id": current_company_id}. Aucune fuite inter-entreprises n'est possible, même en manipulant les identifiants d'URL.

🚀 2. Clé de Sharding & Dénormalisation stratégique

Le champ company_id est obligatoirement dénormalisé dans chaque document de tâche, projet et utilisateur. En Partie II, la clé de distribution composée { company_id: 1, _id: 1 } permettra aux routeurs mongos de router 100% des requêtes d'une entreprise vers un unique Shard hébergeant ses données (Targeted Queries ultra-rapides sans broadcast Scatter-Gather).

🌐 3. Zéro IP en dur & Évolutivité sans recompilation

Le code source ne contient aucune adresse IP, ni port, ni nom d'hôte codé en dur. Il s'appuie exclusivement sur la variable d'environnement MONGO_URI. Passer d'une instance standalone à un cluster distribué avec réplication se fera sans retoucher une seule ligne de code Python.
